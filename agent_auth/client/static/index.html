    Auth Manager

    What Auth Manager is

    Auth Manager is part of Agent Identity. It is a Google-managed vault and broker for third-party credentials. The agent asks Auth Manager for a token when it needs one. The agent never stores tokens.

    Auth providers

    An auth provider is the configuration for one third-party app. It belongs to one project and one location. Types: 3-legged OAuth (3LO, the user gives consent), 2-legged OAuth (2LO, client credentials, no user), and API key. This demo uses one 3LO provider for GitHub.

    Who may use a provider

    IAM controls access. The role roles/agentidentity.user on the provider lets one principal get tokens from it. In this demo, the agent identity has this role, and the demo client service account has it to finish the consent. Grant it on the provider, not on the project.

    The vault

    Auth Manager stores one authorization for each provider and each user ID. The client sends the user ID. Take the user ID only from a verified login, such as the IAP header. Auth Manager does not check the user ID against a login.

    The 3LO consent, in short

    1. The agent asks for a token. There is none, so the client gets a consent URL and a one-time nonce.
    2. The user approves on the provider site. The provider sends a code to Auth Manager, not to the client.
    3. Auth Manager swaps the code for a token and stores it.
    4. The client finishes the flow with the validation state and the nonce. Then the agent gets the token.

    What "Reset Auth Manager consent" deletes

    ItemDeleted?
    Your stored token in the vault, for this provider and your user IDYes
    The record of your consent in Auth ManagerYes, together with the token (inference)
    A refresh token, if one existsProbably yes (inference). A classic GitHub OAuth app normally gives no refresh token

    What the reset does not delete

    ItemWhy it stays
    The auth provider, with its client ID and client secretThe reset acts on one user, not on the provider
    The IAM grants on the providerIAM is separate from the vault
    The access summary recordsThey are history, kept for about 13 months
    Your approval of the app on GitHubGitHub keeps it. To see the GitHub consent page again, also revoke the app tokens on GitHub
    Tokens of other user IDsThe reset uses only your login identity
    The agent, its sessions, and the chatThe reset does not change Agent Runtime

    Revoke in two places

    A revoke on the provider site alone does not reach Auth Manager. Auth Manager keeps the old token, and the next tool call fails (in tests: "MCP session connection lost" or a malformed function call). Revoke in Auth Manager (revokeAuthorization) and on the provider site. To reset both in this demo, use the Demo controls panel.

    Audit

    Access summaries show which agent used which provider for which user. Times are rounded down to the hour. Records stay for about 13 months, and you cannot delete them. They are history, not a list of stored tokens.

    Console view

    The agent Identity tab in the Google Cloud console lists a provider only after the agent has used it. It shows use, not permission. To check permission, read the IAM policy of the provider.
