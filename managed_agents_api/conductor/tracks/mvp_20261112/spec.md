# Spec: Track 1 — MVP (lifecycle, interactions, inline skills)

## Overview

Build the first runnable version of the Managed Agents API demo. A data analyst agent
receives a synthetic sales CSV file from a Cloud Storage bucket that is mounted in its sandbox. The agent runs Python in the
sandbox and writes a chart and a Markdown report. The demo shows the full agent
lifecycle and three kinds of interaction.

## Functional requirements

### FR1. Configuration
- Read `GOOGLE_CLOUD_PROJECT` from `.env`. The location is always `global`.
- Give an `.env.example` file with placeholder values only.
- If `GOOGLE_CLOUD_PROJECT` is not set, stop with an error that states the fix.

### FR2. Access check (`scripts/00_access_check.py`)
- Create the agent `demo-access-check`. Poll the operation. Delete the agent.
- Print the elapsed time of each step.
- On HTTP 403, print the permission that the API names and stop.

### FR3. Agent lifecycle (`scripts/01_lifecycle.py`)
- Create the agent `demo-data-analyst` with `base_agent` `antigravity-preview-05-2026`.
- Poll the long-running operation until `done`. Print the elapsed time.
- Get the agent. List the agents. Print the resource names.
- Update the agent description. Use the SDK if it has an update method.
  If it does not, use a REST `PATCH` request. Record the result in `tech-stack.md`.

### FR4. Cloud Storage source and skill
- Changed on 12 Nov 2026. The API rejects `inline` sources. It accepts only `gcs` and
  `skill_registry` sources.
- `scripts/00b_setup_bucket.py` creates one demo bucket and uploads these files under the
  `agent/` prefix:
  - `agent/AGENTS.md`: the analyst instructions.
  - `agent/skills/report-writer/SKILL.md`: the skill that sets the report format.
  - `agent/data/sales.csv`: synthetic sales data, generated by code in the repository.
- The agent configuration has one `gcs` source: `gs://BUCKET/agent` mounted at `/.agent`.
- The bucket name comes from `DEMO_BUCKET` in `.env`. The default is
  `<project-id>-managed-agents-demo`. The bucket uses uniform access in the `US` multi-region.

### FR5. Single-turn interaction (`scripts/02_interact.py`)
- Ask the agent to analyse `data/sales.csv`, make a chart, and write a report.
- Stream the events. Print the agent text as it arrives.
- At the end, print the interaction ID and the environment ID.

### FR6. Multi-turn session (`scripts/03_session.py`)
- Send a second turn with `previous_interaction_id` and the same environment ID.
- The second turn asks a follow-up question about the first result.
- Print proof that the agent used the first turn.

### FR7. Configuration override (`scripts/04_override.py`)
- Send one interaction with a different `tools` list.
- Get the agent again. Show that the stored configuration did not change.

### FR8. Output files
- Ask the agent to write the chart and the report to `/.agent/output/`.
- List the files under `agent/output/` in the bucket, with sizes and console links.
- If the files are not in the bucket, record this in `tech-stack.md`.

### FR9. Cleanup (`scripts/99_cleanup.py`)
- List the agents. Delete only the agents whose ID starts with `demo-`.
- `--bucket` also deletes the demo bucket and its files, after a second confirmation.
- Ask for confirmation. `--yes` skips the confirmation.
- Print a notice: IAM bindings to a deleted agent identity remain active.

### FR10. REST reference (`scripts/rest_reference.sh`)
- `curl` commands for create, get, list, update, delete, operation, and interaction.

### FR11. Notebook (`notebook.ipynb`)
- The same steps as FR2 to FR9, in the same order.

## Non-functional requirements
- Python 3.11 or later. `google-genai` 3.2.0 pinned in `requirements.txt`.
- Unit tests use a fake client and do not call the network.
- Integration tests run only when `RUN_INTEGRATION=1` is set.
- Terminal output obeys `product-guidelines.md`. Access tokens are masked.
- No project ID, bucket name, or token in the repository.
- `google-cloud-storage` pinned in `requirements.txt`.
- Scripts 02 to 04 use the `demo-data-analyst` agent that script 01 creates.
  Thus the scripts must run in order.

## Acceptance criteria
1. `scripts/00_access_check.py` creates and deletes an agent in the test project.
2. `scripts/01` to `04` run in order without manual changes, after `.env` is set.
3. The agent writes a chart and a report, and they are in the demo bucket.
4. The second turn of the session refers to the first turn.
5. After `scripts/99_cleanup.py --yes`, no `demo-` agents remain.
6. `pytest` passes, and coverage is 70 percent or more.
7. `ruff check` shows no errors.
8. The README states the Preview notice, the setup steps, and what is not built.

## Out of scope
- Output download to the local disk, and a bucket in another project (Track 2).
- MCP server tools (Track 3).
- Google Search and URL context tools.
- Evaluation.
- Web UI.
